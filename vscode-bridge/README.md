# Pi Web VS Code 桥接插件 — 规划记录

> **状态：规划中，尚未实现，开发暂缓。**
>
> 当前目录只记录讨论结论，没有可运行的插件、开发脚手架或 VSIX。
> 用户计划先继续优化现有产品的使用体验，之后统一评估、安排插件开发。
> 本文中的组件、协议和开发阶段均是设计意向，不代表已有功能。

## 1. 目标与原则

让 Pi Web 既可以在浏览器中使用，也可以像侧边栏聊天助手一样在 VS Code 中使用，并共享同一会话的消息、运行状态、消息队列及业务配置。

- **浏览器现有显示和布局不变**，包括桌面与移动端。
- VS Code 使用专用外壳，复用原页面中间主面板，不另写一套聊天产品。
- 插件与浏览器连接**同一个 Pi Web 后端、同一个 AgentSession**。
- 不在插件里再运行一套独立 Agent，不通过两端同时读写会话文件实现同步。
- 插件专属代码、测试和文档集中在本目录；共享主面板、状态逻辑和后端仍留在主项目，不复制分叉。
- 第一阶段优先连接已有服务，暂不负责自动安装、启动或停止后端。

## 2. 已确认的 VS Code 界面

```text
┌────────────────────────────────────┐
│ 会话标题 ▾                  ＋  ⋯ │
│ 会话简要信息                       │
├────────────────────────────────────┤
│                                    │
│          原来的中间主面板          │
│          消息 / 工具调用           │
│                                    │
│          消息队列 / 输入框         │
├────────────────────────────────────┤
│       模型       技能       设置   │
└────────────────────────────────────┘
```

### 顶部：会话信息与操作

- 会话下拉列表支持选择、搜索历史会话；默认当前项目，可查看全部。
- 新建会话入口。
- 显示会话标题和简要信息，优先复用已有模型、运行状态、统计信息，窄面板下精简显示。
- 支持重命名；其他适用的会话操作放入更多菜单，例如在浏览器打开当前会话。
- 危险操作保持明确的确认流程，不为插件降低现有约束。
- 不再额外增加独立的历史按钮，历史会话归入下拉列表。
- 顶部的会话切换与消息内部的分支导航是不同功能，后者仍须保留。

### 中间：复用原主面板

保留消息、工具调用、队列、输入框、当前会话模型和思考等级等现有功能，以及必要的分支、统计、信任提示和确认交互。

不显示网页的左侧工作目录选择、文件浏览器，以及右侧文件面板与文件标签栏。文件、行号链接由受控 IDE 桥接打开到 VS Code 编辑器。

不能简单地只拿 `ChatWindow`：原主面板还有部分逻辑位于 `AppShell`。应先梳理依赖，避免丢失现有功能，也不要把整个网页壳复制进插件。

### 底部：三个固定入口

- **模型**：进入模型配置；不替代输入框中当前会话的模型选择。
- **技能**：进入技能管理。
- **设置**：进入其他现有设置，包括适用的插件和子代理配置。

配置界面复用现有逻辑，适配窄宽度；PWA、浏览器推送、退出网页登录等宿主相关项目需要单独评估，不盲目原样搬入。

### 工作区规则

- 新建会话使用 VS Code 工作区；多根工作区时通过原生选择交互确认。
- 没有工作区时的行为待定，不能静默使用不明确的目录。
- 已有会话保留原 cwd，不因 VS Code 切换工作区而自动改写。
- 打开其他项目的会话应有轻量提示；项目级设置使用明确的目标 cwd。
- 当前客户端浏览哪个会话独立于其他客户端，不互相强制跳转。

## 3. 架构意向

```text
VS Code Webview + Extension Host
  ├─ 专用外壳 + 共享主面板
  └─ 文件定位 / 用户主动添加文件或选区 / 外部打开
                  │
                  │ 命令请求 + 事件订阅
                  ▼
           同一个 Pi Web 后端
           ├─ AgentSession 与运行状态
           ├─ 消息队列与业务配置
           └─ 会话文件
                  ▲
                  │ HTTP / SSE
                  │
             原浏览器界面
```

建议抽象通信层和宿主能力层，但具体加载方案尚未选定：

1. Webview 内嵌服务端专用页面：需验证 CSP、Cookie、鉴权、嵌套消息来源、外部跳转与端口映射。
2. Webview 运行共享界面，由 Extension Host 转发请求和事件：需适配当前相对路径 fetch、EventSource、资源加载与 Next 路由依赖，维护独立的前端打包边界。

先做最小技术验证，再确定方案。不能靠关闭安全检查或允许任意跨源请求实现兼容。

## 4. 同步范围

基本规则：**服务端为唯一事实来源，操作成功后通知客户端更新，断线重连后读取快照恢复。**

| 状态 | 规划行为 |
| --- | --- |
| 已发送消息、回复、工具结果、流式输出 | 共享并同步 |
| 运行、停止、压缩状态 | 共享并同步 |
| 当前会话模型、思考等级、工具选择 | 同步服务端实际生效值 |
| steering / follow-up 队列 | 同步入队、消费与整队清空 |
| 新建、重命名、删除会话 | 各客户端会话列表更新 |
| 全局/项目业务配置 | 保存后通知相关客户端重新读取，明确作用域 |
| 凭据状态 | 同步已配置/已登录状态，不广播原始密钥 |
| 当前查看的会话、滚动、展开折叠 | 客户端独立 |
| 未发送草稿 | 第一版客户端独立 |
| 主题、声音等客户端偏好 | 不默认同步，后续按需评估 |

### 配置语义

- 明确区分当前会话、当前项目和全局配置。
- “配置已保存”不等于“运行会话已生效”。需要 reload 的项目必须显示待重载状态，不自动中断任务。
- 他端修改配置时，不静默覆盖本端未保存的表单；保存时需要适当的冲突检查。
- 设置文件被外部程序或用户手动修改的检测方式尚未确定，不能承诺所有外部编辑都会即时推送。

### 队列边界

现有 `clear_queue` 仅支持清空整个队列；当前封装明确指出 SDK 没有单项出队能力，清空再重排会与 Agent 消费消息竞争。

因此第一版只同步现有能力，**不新增单条删除、编辑或拖动重排**。稳定 ID 本身不能解决 SDK 不支持队列修改的问题。

- 两端同时发送按服务端规则处理，不按客户端的过期显示推断执行状态。
- 请求重试须避免重复入队；断线且执行结果未知时，不盲目重发命令。
- 清空队列不等于撤回已开始执行的消息。
- 客户端重连可以重新读取队列；后端重启后的队列持久化和自动恢复不属于第一版承诺。

### 分支与运行实例

- 会话选择是本地浏览行为；改变同一会话的活动分支是共享状态变化。
- fork、reload、工具切换跨越 Chat-only 边界等可能替换运行实例。
- 其他客户端需要收到失效/替换通知并重新读取状态，不能继续对着旧实例或旧上下文发送。
- 扩展弹窗应保持服务端单次结算，并验证一端处理后另一端关闭、超时、重连恢复等行为。
- 需要版本/实例标识等机制防止迟到的响应回滚新状态；具体协议后续定义。

## 5. 已发现的实现风险

以下是规划阶段的代码观察，实施前应重新核对当时版本。

### 侧栏承载了数据逻辑

`components/SessionSidebar.tsx` 不只是视图，还承载会话加载、运行状态轮询、初始恢复、cwd 回调和后台完成通知等逻辑。

不能直接删掉它，也不应用 CSS 隐藏后继续挂载文件树。应抽取共享状态逻辑，让浏览器侧栏和插件顶部选择器复用。

### 浏览器回归风险

通过显式宿主模式选择布局，不根据窄窗口或移动端断点判断是否为插件。插件样式应隔离；浏览器继续默认路径。

“浏览器布局不变”不等于“会话操作互不影响”：一端停止任务、改配置或清空队列，会影响另一端正在查看的同一会话，这是共享后端的预期行为。

### 连接与生命周期

- 关闭/隐藏 Webview 只释放客户端资源，不发送 abort，也不停止独立后端。
- 重新打开要恢复会话选择与完整状态，不能依赖 Webview 定时器持续运行。
- 下拉列表使用会话目录/运行状态查询，不为每个历史会话建立 SSE 或创建 Agent。
- 当前 lease 续期按会话续所有租约，多端环境下需要检查失联连接清理和保活资源占用；是否改为连接级续期待验证。
- 多客户端可能重复发声或弹通知，需定义通知归属/去重策略，不能直接依赖两种宿主共享 localStorage。

### 安全与文件一致性

- 桥接动作使用白名单和结构校验，不允许网页或模型输出调用任意 VS Code 命令。
- 校验消息来源、文件路径、工作区信任和外部 URI；不绕过后端现有文件访问边界。
- 不将服务密码、模型密钥放入 URL、日志、Webview HTML 或持久化页面状态。
- 区分 VS Code 工作区信任和 Pi 项目信任，不默认视为等价或自动互相授权。
- 用户主动添加选区可携带未保存文本；添加路径一般由 Agent 读取磁盘版本，两者语义应明确。
- 不自动保存用户文件，不静默上传全部打开的编辑器内容。
- Agent 改写磁盘文件与编辑器未保存缓冲区的冲突要提示，不强制覆盖用户编辑。

### 构建隔离与远程工作区

- 根 TypeScript 配置当前扫描子目录 TS/TSX；未来插件需要独立配置及根项目排除边界。
- 同时隔离 lint、测试、依赖目录和打包产物，不把插件构建混入 Next.js。
- 插件与后端需要版本/能力识别；不只检测某个端口是否有 HTTP 响应。
- SSH、WSL、Dev Container 的后端位置、URI/路径和端口映射尚未验证；不能把远程 cwd 当成本机路径。
- 第一版优先本机桌面 VS Code + 已有后端；不默认承诺 vscode.dev 或远程场景支持。
